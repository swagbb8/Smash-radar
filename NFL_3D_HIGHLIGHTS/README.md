# 3D Football Highlight Maker (Blender)

Describe an American football play — as a JSON file or in plain English — and get a cinematic, stylized 3D
highlight: 11-on-11, a real stadium, automatic camera cuts, a slow-motion replay, broadcast graphics and sound,
exported as an MP4. Everything is generated by Python through Blender's API. No footage, no real faces, no logos.

```
play JSON / plain English ─► play_parser ─► simulation (22 players + ball physics + event timeline)
        ─► scene_builder: stadium · lighting · players · football · cameras · replay · effects
        ─► render (Cycles) ─► hud (score bug, TOUCHDOWN, REPLAY…) + audio ─► MP4
```

## 1. Install

- Python **3.11** and FFmpeg.
- `pip install -r requirements.txt` (installs `bpy` — Blender as a Python module — plus Pillow and numpy).

That's all. You do **not** need to install Blender separately to generate videos. If you prefer the Blender app
(4.2 or newer), everything also runs inside it — see section 3.

## 2. Generate a highlight

Run these from the `NFL_3D_HIGHLIGHTS` folder.

| What | Command |
|---|---|
| Build the scene and save a `.blend` | `python blender/main.py --play plays/example_touchdown.json` |
| Fast preview video (720p) | `python blender/main.py --play plays/example_touchdown.json --preview` |
| **Final render** (1080p, motion blur) | `python blender/main.py --play plays/example_touchdown.json --render` |
| Other examples | `--play plays/example_interception.json`, `example_sack.json`, `example_long_pass.json`, `example_long_run.json` |
| From plain English | `python blender/main.py --text "QB rolls left, avoids a defender, throws a 35-yard pass to a receiver running a post route, receiver catches it over a defender and scores." --preview` |
| Wide video | add `--aspect 16:9` (default is vertical `9:16`) |
| Quality | add `--preset DRAFT`, `PREVIEW`, `STANDARD`, `HIGH` or `CINEMATIC` |
| Look | add `--lighting DAY`, `NIGHT`, `PRIMETIME` or `CINEMATIC`; `--weather rain` or `snow`; `--camera broadcast` |
| QA contact sheet | add `--sheet 18` (18 evenly spaced frames with graphics, tiled into one image) |
| Timeline only, no Blender | `python blender/main.py --play plays/example_touchdown.json --info` |

The video lands in `renders/<play name>/<play name>.mp4`.

Rendering is resumable (frames already on disk are skipped) and can be split across machines:
`--render --frames 1:120` renders one chunk; `--finish` adds graphics + sound and encodes once all frames exist.
If you ever want to encode by hand: `ffmpeg -framerate 30 -i renders/NAME/composited/%05d.jpg -i renders/NAME/audio.wav -c:v libx264 -crf 18 -pix_fmt yuv420p -c:a aac -shortest NAME.mp4`

### Render presets

| Preset | Size (long side) | FPS | Notes |
|---|---|---|---|
| DRAFT | 960 | 24 | quickest look |
| PREVIEW | 1280 (720p) | 30 | fast render |
| STANDARD | 1920 (1080p) | 30 | motion blur |
| HIGH | 1920 (1080p) | 60 | motion blur |
| CINEMATIC | 2560 (1440p) | 60 | most samples |

### Rendering in the cloud (no computer needed)

The repository has a GitHub Actions workflow, **3D highlight (Blender)**. Open the Actions tab, choose it, press
**Run workflow**, type the play in plain English (or name a file from `plays/`), and it renders the frames on up to
20 machines at once. The finished MP4 is attached to the run and saved in the `highlights-3d` release.

## 3. Using it inside Blender

1. Open Blender 4.2+.
2. `blender --python blender/ui.py` — or open `blender/ui.py` in the Scripting tab and press **Run Script**.
3. In the 3D viewport press **N** and open the **Football** tab: **3D FOOTBALL HIGHLIGHT MAKER**.

Buttons: LOAD PLAY · BUILD SCENE · SIMULATE PLAY · GENERATE CAMERAS · GENERATE REPLAY · RENDER PREVIEW ·
RENDER FINAL · EXPORT VIDEO. The panel also shows Play Type, Duration, Home Team, Away Team, Resolution, FPS and
Visual Style. Headless: `blender -b -P blender/main.py -- --play plays/example_touchdown.json --preview`.

## 4. The play format

Only `play_type` (or `description`) is required. Everything else has a sensible default.

```json
{
  "play_type": "deep_pass_touchdown",
  "description": "shown in the caption",
  "yards": 50,
  "teams": {
    "HOME": {"name": "Sharks", "abbr": "SHK", "primary": "#0b6e7a", "secondary": "#ffb81c",
             "helmet": "#0b6e7a", "jersey": "#0b6e7a", "pants": "white", "socks": "#0b6e7a"},
    "AWAY": {"name": "Wolves", "abbr": "WLV", "primary": "red", "secondary": "silver"}
  },
  "quarterback": {"team": "HOME", "number": 12, "scramble": false},
  "receiver":    {"team": "HOME", "number": 11, "route": "post", "side": "left", "speed": 1.0},
  "defender":    {"team": "AWAY", "number": 24, "coverage": "man", "bites": true},
  "runner":      {"team": "HOME", "number": 28, "direction": "right"},
  "kicker":      {"team": "HOME", "number": 3},
  "ball":   {"throw_time": 3.6, "catch_time": 5.8, "air_yards": 38, "spin_rate": 32, "target": "receiver"},
  "catch":  {"one_handed": false, "jump_ball": false, "sideline": false, "over_shoulder": false},
  "moves":  ["stiff_arm", "spin", "hurdle", "broken_tackle"],
  "field":  {"yard_line": 50},
  "result": "touchdown",
  "return_yards": 60,
  "scoreboard": {"quarter": "Q3", "clock": "4:32", "down": "2ND & 7", "home": 17, "away": 20},
  "player_names": {"11": "D. Rivers"},
  "lighting": "PRIMETIME",
  "weather": "none",
  "camera_style": "cinematic",
  "replay": true,
  "effects": {"amount": 1.0, "dof": true}
}
```

- **play_type** — free text; these all work: `touchdown pass`, `deep pass`, `short pass`, `incomplete pass`,
  `interception`, `pick six`, `sack`, `sack fumble`, `fumble`, `run`, `long run`, `tackle for loss`, `screen`,
  `hail mary`, `kickoff return`, `punt return`, `field goal`, `two point conversion`.
- **result** — `touchdown`, `tackle`, `interception`, `incomplete`, `sack`, `fumble`, `good`, `no_good`.
- **routes** — slant, drag, curl, comeback, out, in, post, corner, go, fade, wheel, screen, cross, seam, dig.
- **moves** — stiff_arm, spin, hurdle, broken_tackle (each one is played against a defender, in slow motion).
- **ball timing** — `throw_time` / `catch_time` are honoured as long as the ball can physically get there; the
  flight is a real ballistic arc (gravity 9.8 m/s²) from the QB's hand to the catch point.
- **colors** — `#rrggbb` or names (red, blue, navy, white, silver, black, gold, green, orange, purple, teal…).
- The team named in `quarterback` / `runner` / `kicker` (or `defender`, for defensive plays) is the one making the
  highlight. HOME wears the team colour, AWAY wears white.

### New play from plain English

```
python blender/main.py --text "QB rolls left, avoids a defender, throws a 35-yard pass to a receiver running a post route, receiver catches it over a defender and scores." --save-json plays/my_play.json --preview
```

`play_parser.parse_text()` reads the yardage, play type, route, side, scramble, catch style, moves, jersey numbers
(`WR #11`), field position (`from the 30-yard line`) and result, and writes the same JSON structure as above — so
you can tweak the file and re-render.

## 5. What is automated, and what isn't

**Fully automated**
- Field (regulation proportions, yard lines, hash marks, numbers, painted end zones), stadium (two-deck bowl with
  crowd, light towers, scoreboard, tunnel, benches, goal posts, pylons), four lighting presets, rain / snow.
- Players: body, helmet with facemask and visor, shoulder pads, numbered jersey, pants, socks, cleats, gloves —
  generated in code. Per-team colours, per-player numbers, build by position, attributes (speed, strength…).
- 11-on-11 simulation: formations, routes, blocking, coverage, pursuit, tackles, broken tackles, fumbles, kicks.
- Animation: idle / jog / sprint / backpedal from motion-capture clips, plus procedural stance, snap, block,
  throw, handoff, catch, one-hand catch, jump, dive, tackle, fall, stiff arm, spin, hurdle, kick, celebrate.
- Football: ballistic flight, spiral, end-over-end kicks, bounces, carried in the arm.
- Ten camera types, cut automatically on the play's events, with focus tracking and depth of field.
- Replay (40–60 % speed, different camera), broadcast graphics, sound, MP4 export.

**Needs assets or manual work**
- More motion-capture actions. Drop any Mixamo-rig `.glb` with clips named `idle`, `walk`, `run` into
  `assets/animations/` and it is used automatically (the first `.glb` found is the skeleton source). Tackles,
  throws and catches are procedural, so they look simpler than motion capture.
- Real team logos and real player likenesses are deliberately not included.
- Faces are hidden behind a tinted visor by design.
- Final-quality renders are slow on a computer without a strong CPU — use the cloud workflow above.

## 6. Layout

```
blender/main.py            command line
blender/play_parser.py     plain English -> play JSON -> normalized play
blender/simulation.py      players, assignments, ball physics, events (pure Python)
blender/scene_builder.py   assembles and keyframes the whole scene; effects; render presets
blender/player_system.py   procedural player, uniforms, attributes
blender/animation_system.py  clip blending + procedural football actions (FK solver)
blender/football_system.py   ball model, trajectory helpers, ball animation
blender/camera_system.py     shot director + camera rig
blender/replay_system.py     output timeline: live play, replay, celebration
blender/stadium.py  lighting.py  hud.py  audio.py  render.py  ui.py  utils.py  ci.py
assets/   animations (skeleton + clips), fonts, generated texture caches
plays/    example plays
renders/  output
```
